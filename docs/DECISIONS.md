# Decisions, assumptions and open items

Status: see the numbered entries below and `docs/TODO.md` for what is built and what is left. The plugin has its own admin menu (podcast list, New podcast, one sub-item per podcast, Settings), podcast details and feed files, episodes, and the Podcasting 2.0 tags listed in the breakdown further down; Location search is built (0.11.0, decisions 63 to 66). Adopting an existing feed is built (0.12.0, decisions 67 to 70). The save-time lost-tag check and chapters.json upload are built (0.13.0 and 0.14.0, decisions 71 to 74); safe file names and the time splits import are built (0.15.0, decisions 75 to 77); tabs and the tidier look are built (0.16.0, decision 78); WordPress posts for episodes and a podcast page are built (0.17.0, decisions 79 to 82); admin tidy-up (lists with Add/Edit/Remove, one funding link, Live episodes on the Episodes tab, mandatory episode Explicit, install-zip fix) is built (0.18.0, decisions 83 to 88); chunked audio upload is built (0.19.0, decision 89). Not built: Podcast Index and Podping.

## Product decisions (stated by the owner)
- **Podcasting 2.0 first** (owner, 2026-11-21): the target is Podcasting 2.0 apps and the podcast namespace. Apple Podcasts, Spotify and similar services are not Podcasting 2.0 compliant and are **secondary accommodations**: their extra requirements are supported only as warnings or optional fields, never as blockers, and never at the cost of a Podcasting 2.0 feature. Written into `AGENTS.md` as rule 9.
- Project and plugin name is **PodPublisher** (decided 2026-11-20). Description: a WordPress plugin to manage Podcasting 2.0 feeds and files.
- Naming scheme: see `AGENTS.md` (slug and text domain `podpublisher`, prefix `podpub` / `PODPUB_`).
- Versioning: starts at **0.1.0**. Major version changes (including moving to 1.0.0) need the owner's explicit approval; features and fixes before that are minor/patch bumps.
- Admin menu (owner request, 2026-11-20): a top-level **PodPublisher** item (not under Settings). Its page lists the managed podcasts and has **New podcast** and **Adopt a feed**. Its sub-items are: All podcasts, one item per managed podcast (in A to Z order), then Settings (general plugin settings, last).
- Files on disk (owner request, 2026-11-20): Settings has a **Podcast folder** (default: a `podpublisher` folder inside the WordPress uploads folder) and a **Public address** for it. Each podcast has its own sub-folder holding its feed XML, its image and its other files; each episode has its own sub-folder inside the podcast folder. Folder and file names contain no spaces or special characters: spaces become `_` and anything outside A-Z a-z 0-9 `_` `-` is removed (`PodPub_Storage::slug`).
- Repo layout and working rules copied from `ghmattf/publisher-feed-generator` (read-only reference).

## Assumptions to verify (not confirmed)
1. Public GitHub repo `ghmattf/podpublisher` (assumed, same as the owner's other plugin repos).
2. Minimum WordPress 5.8 and PHP 7.4, copied from the feed generator plugin.
3. Release workflow and the PR-driven version bump work the same as in the feed generator.

4. (0.2.0.) Managed podcasts are stored as records of a private post type `podpub_feed` (no front-end URL, no WordPress editor screen), so they survive in the normal WordPress tables and are removed on uninstall only if the Settings box is ticked. Assumption: this is the right store; a custom table is the alternative.
5. (0.2.0.) Access needs the `manage_options` capability (administrators). Assumption: editors should not manage podcasts; change `PodPub_Admin::CAP` if they should.
6. (0.2.0.) The menu is built on every admin page load with one query for the podcast list; with a very large number of podcasts the sidebar would get long. Not a concern at small scale.
7. (0.2.0.) "New podcast" asks only for a title and creates the record, then opens that podcast's page, which is a placeholder.

8. (0.3.0.) Names keep the case the user typed (`My_Show`, not `my_show`), as only the spaces rule was requested. Assumption: lower-casing would be safer on case-sensitive servers and for URLs; two titles differing only by case get separate folders (`My_Show`, `my_show`) on Linux but would collide on Windows/macOS, where the second becomes `my_show_2`. Easy to change in `PodPub_Storage::slug`.
9. (0.3.0.) A duplicate name gets `_2`, `_3`, ... (`My_Show`, `My_Show_2`). Names are limited to 60 characters. A folder is never renamed after it is made (feed URLs must not change), even if the podcast title changes. If the title has nothing usable (for example only symbols) the name is `podcast` or `episode`.
10. (0.3.0.) A folder entered in Settings must be a full path with no `..` and only letters, numbers, `.`, `_` and `-` in each folder name; a path or address that breaks that is refused and the old value kept. A folder outside the uploads folder also needs its public address. A folder the web server cannot write to is saved with a warning. Each folder gets an empty `index.html` so servers do not list its contents. Changing the setting does not move podcasts already created; they stay where they are (their folder name is stored, the base is not), so after changing it, existing podcasts would be looked for in the new folder. **Not handled yet:** moving existing podcast folders when the setting changes.
11. (0.3.0.) Episode folders: the function exists and is tested (`PodPub_Storage::create_episode_dir`) but nothing calls it yet because episodes are not built.

12. (0.4.0, chunk A.) Each podcast's page has a details form: title, description (required, up to 4000 characters), language (list), category (list of the 19 top-level categories used by the `itunes:category` tag; no sub-categories yet; optional), explicit, type (episodic or serial), author, website (http or https), copyright, owner name and email, and show art. Saving checks everything first and saves nothing if any field is wrong. A title change updates the podcast's name in the menu but never its folder or feed address.
13. (0.4.0.) The feed is written to `{podcast folder}/{folder name}.xml` on every save (RSS 2.0 with the itunes, atom, content and podcast namespaces): channel title, link, description, language, copyright, lastBuildDate, generator, atom self link, itunes author, owner, image, category, explicit, type, `podcast:guid` and `podcast:medium` podcast. Optional tags are left out when empty. The `itunes:` tags are written because Podcasting 2.0 apps and Podcast Index also read them (assumption, not re-checked against each app), not because Apple needs them. It is written to a temporary file and renamed so a half-written feed is never served. Episodes are added as items since 0.5.0 (see 19 to 27). A podcast with no published episodes still gets a feed file; directories will not accept it until it has at least one (assumption: writing it anyway is fine).
14. (0.4.0.) `podcast:guid` is made once, on the first save, and never changes: a UUID version 5 of the feed address (scheme and trailing slash removed) with the podcast namespace, as the Podcast namespace specification says (checked against its published example and an independent calculation); a random UUID if the public address is not known. Assumption: if the feed address later changes (for example the Podcast folder setting is changed), the GUID stays, which is what the specification wants, but the feed will need `itunes:new-feed-url` (not built).
15. (0.4.0.) Show art: JPEG, PNG or GIF (checked by reading the file, not the name; changed in 0.4.1 to add GIF at the owner's request, because Apple Podcasts and Spotify are secondary, see the Podcasting 2.0 first decision), up to 10 MB, stored as `cover.jpg`, `cover.png` or `cover.gif` in the podcast folder; the uploaded file's own name is never used and an old cover of another type is removed. A GIF is accepted with a warning that some directories (for example Apple Podcasts and Spotify) only take JPEG or PNG. A picture that is not square, or not between 1400 and 3000 pixels, is accepted with a warning, not refused (assumption: warn only, because the owner may want to use it anyway; the size range is what directories expect, not something the podcast namespace requires). Animated GIFs are stored as they are; whether a Podcasting 2.0 app animates them is not tested. Not checked: file size in pixels over 3000, colour profile, or the picture being corrupt beyond its header. Show art is not resized or converted.
16. (0.4.0.) Text going into the feed has XML-forbidden and control characters removed, and is written through an XML writer (not string joining), so `&`, `<` and quotes in titles cannot break the feed.
17. (0.4.0.) Uninstall (when ticked) deletes the podcast records and settings but **leaves the files on disk** (feeds, images, episodes), because feeds are live and may be registered with directories. Assumption: this is wanted; it matches the feed generator plugin's rule that published XML is never deleted.
18. (0.4.0.) Only administrators can save details (`manage_options`, a nonce, and uploads only accepted when PHP says the file was really uploaded).

19. (0.5.0, chunk B.) Episodes are private records (post type `podpub_episode`, child of the podcast record). Each has its own folder inside the podcast folder, made from its title by the same naming rules, holding its audio as `{folder}/{folder}.{ext}`. The folder name never changes when the title does, and the uploaded file's own name is never used. Two episodes with the same title get `_2`, `_3`.
20. (0.5.0.) Episode fields: title, description (plain text, required, up to 4000), show notes (optional, up to 50000, limited HTML: a with http/https/mailto links, b, strong, i, em, br, p, ul, ol, li, h2-h4, blockquote; written as `content:encoded` in CDATA), date and time (in the **site's time zone**, shown as the feed's UTC `pubDate`), duration, season, episode number, type (full, trailer, bonus) and status (draft or published). Saving checks everything first and changes nothing if anything is wrong (a new episode's folder and record are only created after the checks pass).
21. (0.5.0.) Audio: MP3, M4A, OGG, OPUS, WAV or FLAC. Checked by file extension **and the file's first bytes** (so a text or PHP file renamed `.mp3` is refused); the browser's claim is ignored. Stored with the right `enclosure` MIME type and its exact size in bytes. Uploading another file replaces the old one, and audio of a different type is removed. **Limit:** the server's PHP upload limit (the form shows it; a too-large upload gives a clear message). Nothing else limits size. Larger files can instead be copied into the episode folder and picked, or hosted elsewhere (decisions 28 and 29).
22. (0.5.0.) Duration: typed as seconds, m:ss or h:mm:ss; if left empty and a file is uploaded it is read from the audio with WordPress's own reader when available (assumption: this works for MP3 and M4A on most hosts; not tested on a real site), otherwise it is left out of the feed. Written as `itunes:duration` (h:mm:ss).
23. (0.5.0.) Each episode gets a permanent `guid` (random UUID, `isPermaLink="false"`) when first saved, never changed. Season and episode numbers are written as `podcast:season` and `podcast:episode` (Podcasting 2.0) and also as the `itunes:` tags; `itunes:episodeType` is always written.
24. (0.5.0.) What is in the feed: only episodes that are **published**, **have audio**, and are dated **now or earlier**, newest first. A draft, an episode without audio, or a future-dated one is left out. Publishing without audio is refused. **No automatic scheduling:** a future-dated episode only appears when the feed is next written after its time (any save of the podcast or an episode), and the form warns about this. Assumption: a real scheduler (WP-Cron) is a later chunk.
25. (0.5.0.) Deleting an episode (button with a confirmation) removes its record and its whole folder, including the audio, then rewrites the feed. Folders are only removed when the name matches the safe-name rule and sits inside that podcast's folder; symbolic links are removed, never followed. An episode can only be edited or deleted through its own podcast.
26. (0.5.0.) The feed is rewritten (atomically) on every podcast or episode save and delete. If the podcast details have not been saved yet (no description), an episode saves with a warning and the feed is written once the details are saved.
27. (0.5.0.) Not done in this chunk, by design: episode images, per-episode explicit flag, chapters, transcripts, per-episode value/funding/location/cast (chunks C and D), a podcast delete button, and moving or renaming folders.

28. (0.6.0, owner request.) **Audio hosted elsewhere:** an episode can use an https address instead of a file. The address must start with https:// and have no spaces or quotes. Size and type: worked out from the address's file extension and by asking the other server (a HEAD request through `wp_safe_remote_head`, the safe sibling of `wp_safe_remote_get`: https only, no private addresses, 10 seconds, 3 redirects), or entered by hand (size in bytes, type chosen from a list). The server is only asked when the address is new or the size or type is missing. If it cannot be reached, the address is saved with a warning; if the type cannot be worked out, the save is refused with a request to choose the type. **The file itself is not checked** (no header check as for uploads), and an unknown size warns. No local file or copy is made; the episode folder is still created.
29. (0.6.0, owner request.) **Pick a file copied into the episode folder** (for example by FTP, for files bigger than the PHP upload limit): the episode form lists the audio files in the episode's folder (types as for uploads; hidden files, sub-folders, links and non-audio files are not listed). Picking one checks its first bytes like an upload. A name with spaces or special characters is **renamed** to a safe one (`My Big File (final).MP3` becomes `My_Big_File_final.mp3`; a clash gets `_2`); a safe name is kept as it is. The new episode form says to save the episode first, because its folder does not exist until then. Picking one file does not delete the others in the folder.
30. (0.6.0.) Switching an episode's audio source replaces which file the feed uses, but **does not delete files** left behind (an earlier upload or picked file stays in the episode folder; deleting the episode removes them all). Assumption: leaving files is safer than deleting something the owner copied in.
31. (0.6.0, owner asked for an explanation.) **Why an empty `index.html` is written into the podcast folder, every podcast folder and every episode folder** (`PodPub_Storage::ensure_dir`, only when missing): many web servers (Apache with directory listing on, nginx with `autoindex on`) show a list of every file in a folder that has no index file. Without it, anyone could open `.../podpublisher/My_Show/` and browse all folder and file names, including the audio files of drafts. With it, that address shows a blank page. WordPress does the same in its own folders (`index.php`). **Limits:** it does not hide a file whose exact address is known, so an unpublished episode's audio is *unlisted*, not private; and it does nothing on a server that already refuses folder listings. It is harmless to feeds and apps, is ignored by the audio picker, and is removed with the folder. Cost: one empty file per folder. Option if unwanted: a Settings switch to turn it off (not built).
32. (0.6.0.) **Known limit: drafts are not private.** Files of draft or future-dated episodes are in the public folder and can be fetched by anyone who knows or guesses the address. Folder names come from titles, so they are guessable. Not built: private storage or secret file names.
33. (0.7.0.) **Chunk C: Podcasting 2.0 tags**, on the podcast page (one "Podcasting 2.0 tags" form) and in the episode form: funding, location, person (cast), license, value with recipients, block and podroll (podcast only), and value time splits (episode only). Checked against the Podcast namespace spec (podcasting2.org and the GitHub tag pages, 2026-11-21). One bad field saves nothing; an empty form removes the tags from the feed.
34. (0.7.0.) **Web addresses in these tags must be https://.** The spec says hyper-text addresses "must be given as https: and not http:", so funding, person, license, podroll and remote-feed addresses refuse http://. (The podcast's own website address and the public file address in Settings still accept http://.)
35. (0.7.0.) **Location follows the 2025 revision of the tag:** several locations are allowed (up to 10); the name is required (up to 128 characters); `rel` is subject (default, written explicitly) or creator; `geo` is written as a geo URI; `osm` is N, W or R plus digits; `country` is a two-letter code (checked for shape, not against the ISO list). The spec marks the attributes recommended, so each is optional here.
36. (0.7.0.) Assumptions: person `role` and `group` are not checked against the spec's taxonomy (any short lower-case words are kept; the form says so); recipient splits are not forced to add up to 100; a time split must have a remote feed GUID and a start and duration, and an episode with time splits must have a value block with recipients. Row lists show three spare empty rows per save (no "add row" button yet).
37. (0.7.0.) Not built in chunk C: `podcast:locked`, `podcast:complete`, `podcast:txt`, importing splits from The Split Kit, valueRecipient-style time splits (only remote-item splits), checking that a remote feed exists, and tag inheritance (an episode with no value block of its own uses the podcast's, by the app, not by this plugin). Known limit: a stray `<` typed in a text field is stripped by WordPress's text cleaner (not tested on a real site).
38. (2026-11-21, owner asked for the features in this reference feed: https://phafe.com/wp-content/uploads/rssfeed/v4v_music_spotlight/V4V_Music_Spotlight.xml, made with Sovereign Feeds.) Tags it uses, and where they land: channel `podcast:complete`, `managingEditor`, `itunes:keywords`, a full `<image>` block with width/height/description, an empty `category` (chunk A refinements); item `itunes:subtitle`, `itunes:summary`, `itunes:keywords`, per-episode `itunes:image`, per-episode `itunes:explicit`, `podcast:chapters` and `podcast:alternateEnclosure` with `podcast:source` (chunk D); `podcast:liveItem`, `podcast:txt`, `podcast:trailer`, `podcast:images` are not in that feed but are in the namespace (chunks D and H). Chunk C tags in it (funding, person, value, valueRecipient with lnaddress and node, valueTimeSplit with remoteItem, block) are all covered. Its `xmlns:podcast` address is a GitHub page; PodPublisher uses the spec's `https://podcastindex.org/namespace/1.0`, which is the correct one.
39. (0.8.0.) **Chunk D (part 1): chapters, transcripts, soundbites, alternate enclosures, cross-app comments, and the channel tags complete, locked and txt.** Checked against the Podcast namespace pages (podcasting2.org, 2026-11-21); `complete` and `txt` are from my knowledge of the spec (their pages were not readable): complete = `yes`; txt = text up to 4000 characters with an optional purpose.
40. (0.8.0.) **Chapters** are typed into an editor on the episode form (start as seconds, m:ss or h:mm:ss; title; optional picture and link). PodPublisher writes them as **`chapters.json`** (JSON chapters 1.2.0, sorted by start time) in the episode folder and writes `<podcast:chapters url=... type="application/json+chapters">` pointing at it. Alternatively one https address of a chapters file hosted elsewhere can be entered; using both is refused. Emptying the list deletes `chapters.json`. Deleting the episode removes it with the folder. Assumption: I did not read the JSON chapters spec page itself (only the tag page); the file uses only `version`, `chapters[].startTime`, `title`, `img`, `url`, which are the fields I know from that spec.
41. (0.8.0.) **Transcripts** are links only (https address, file type chosen from text/plain, text/html, text/vtt, application/x-subrip, application/json; optional language and `rel="captions"`). A transcript file can be copied into the episode folder and linked by its address, but there is no upload or file picker for it yet.
42. (0.8.0.) **Soundbites**: start and length in plain seconds (decimals allowed, for example 73 or 60.5), optional title up to 128 characters. The 15 to 120 second recommendation is in the form's text, not enforced.
43. (0.8.0.) **Alternate files** (`podcast:alternateEnclosure` with one `podcast:source` each): https address and MIME type required; size, bitrate, height, language, title, group (`rel`), codecs and Default are optional. Not built: more than one source per alternate file, torrent sources, `podcast:integrity`.
44. (0.8.0.) **Comments (`podcast:socialInteract`)** on the podcast and on each episode: protocol (any short lower-case word; the spec's own list was not checked, so a misspelt protocol is accepted), the address of the post, optional account id, account address and priority. The protocol `disabled` writes the tag with no other attributes, as the spec says.
45. (0.8.0.) **Channel: Complete, Locked, Text records.** Locked is yes, no or not set, with an optional owner email (used by other platforms to check a move). Not a security feature of this plugin.
46. (0.8.0.) Still to do in chunk D / from the reference feed (decision 38): per-episode picture, explicit flag, subtitle, summary and keywords; `podcast:trailer`, `podcast:images`, `podcast:txt` on episodes, `podcast:liveItem`; a transcript upload or picker; `podcast:integrity`. A bigger form is the cost of this chunk: the episode form now has many sections (they are all open, one long page).
47. (0.8.1, owner's request.) **Keysend removed from the value block.** Payments are Lightning address only: the form has no method choice, no "Node" recipient type and no custom key/value; the feed always writes `<podcast:value type="lightning" method="lnaddress">` with `type="lnaddress"` recipients. Split, fee and the suggested amount stay. Podcasts saved with 0.7.0 or 0.8.0 that used keysend recipients: those recipients are not shown on the form and are not written to the feed (so the value block disappears from the feed if it had only keysend recipients); enter them again as Lightning addresses. This replaces the keysend and custom-record parts of decisions 33 and 36.
48. (0.9.0.) **Explicit is a required yes/no choice** on the podcast details ("This feed contains explicit content"), blank by default; saving without choosing is refused. A podcast saved before 0.9.0 with the tick box shows Yes (ticked) or No (unticked). A podcast with no answer yet writes no `itunes:explicit` tag. Episodes have their own Explicit select: Same as the podcast (writes nothing), Yes or No.
49. (0.9.0.) **`managingEditor`** is written from the owner details already on the form, as `email (Name)` (just the email if there is no name, nothing if there is no email), so there is no second field to fill in. Podcast **keywords** are written as `itunes:keywords`.
50. (0.9.0.) **Smaller pictures for `podcast:images`.** When show art (or an episode picture) is uploaded, copies 300, 600, 1000 and 1500 pixels wide are made next to it for every width smaller than the original (`cover-300.jpg`, `image-600.png`, and so on), and the feed gets `<podcast:images srcset="...">` listing them with the original last. A new upload removes the old copies. **Limits:** a GIF is not resized (an animated one would stop moving), so it gets no copies and the user is told; show art uploaded before 0.9.0 has no copies until it is uploaded again; there is no "make copies again" button yet. WordPress's own image editor is used when present (GD or Imagick) and PHP's GD otherwise; only the GD route was run in the tests, so the WordPress-editor route is unverified on a real site.
51. (0.9.0.) **Episode extras:** subtitle (up to 255 characters, `itunes:subtitle`), summary (up to 4000, `itunes:summary`), keywords, explicit, and a picture (saved in the episode folder as `image.jpg|png|gif`, written as `itunes:image` plus `podcast:images`). The picture can be removed with a tick box. Episode-level `podcast:txt` text records were added too.
52. (0.9.0.) **Trailers** (`podcast:trailer`, podcast level, up to 5): title, https address and published date required; size, type and season optional. **Live episodes** (`podcast:liveItem`, up to 10): title, status (Pending, Live, Ended), start and optional end, https stream address, stream type (default audio/mpeg), optional link (written as `podcast:contentLink`). The status is changed by hand and saved; nothing switches it automatically (that needs scheduling, not built). The item guid is worked out from the podcast's guid and the title, so it stays the same when the status changes but changes if the title does. Times are entered in the site's time zone and written in UTC. Assumption: I could not read the `liveItem` spec page, so the tag follows my knowledge of it (status, start, end attributes; title, guid, enclosure with length 0, content link).
53. (0.9.0.) **Alternate files** can have a checksum (`podcast:integrity`, kind sri or pgp, with its value); kind and value go together.
54. (0.9.0.) **Transcript files**: on the episode form a transcript can be uploaded (txt, html, vtt, srt or json, up to 5 MB, stored in the episode folder under a safe name, never overwriting) or picked from files copied into the folder; either is added to the transcript list with its type when the episode is saved. The language and "captions" can then be set in the list. Both need the public address of the files to be set in Settings.
55. (0.9.0, TODO 18.) **Automatic episode numbers.** A new *full* episode saved with no number gets one more than the highest number used in its season (episodes with no season count as one group). Bonus and trailer episodes are not numbered. The new-episode form already shows the number and carries on the season from the latest episode, and both can be changed. Editing a saved episode and clearing its number leaves it empty. Numbers are never changed after they are given; there is no renumbering.
56. (0.9.0, TODO 11; changed in 0.9.1.) **Add episode** offers two buttons: empty (season and number carried on from the latest episode) or copying details from the latest episode (by date). Copied (0.9.1): title, description, show notes, subtitle, summary, keywords, season, episode type, people, funding, location, licence, payments and comments; the episode number is the next one. Not copied: guid (each episode needs its own), date and time (set to now), explicit (left at "same as the podcast"), audio, duration, chapters, transcripts, soundbites, alternate files, picture, time splits.
57. (0.9.0, TODO 16.) **People role and group are drop-down lists** from the Podcast namespace people taxonomy: 11 groups and 62 roles (the roles in the groups' own order). The official taxonomy file could not be read, so the lists come from a parser's copy of it, and I worked out which role belongs to which group from the order of that list; please check them against the spec (`PodPub_P20::taxonomy()`). Rules: a role alone gets its group filled in (cast, the default, is not written); a role must belong to the group chosen with it; a group alone is refused; "editor" is in two groups (writing and video post-production), so with no group it is taken as writing. The group "misc" has no roles in the copy I used. Roles or groups typed by hand before 0.9.0 show as "(not in the list)" and are refused until changed. Not included: "co-creator" and "performer", which some older lists have.
58. (0.9.0.) Bug found while testing: the transcript picker listed the empty `index.html` that every folder holds; it is now left out. Chunk D is finished with this release.
59. (0.9.1.) **Text records (`podcast:txt`) removed.** I had added them from my own reading of the spec; the reference feed (V4V Music Spotlight) has no `podcast:txt` and no `podcast:locked`, and the owner said they are not needed. The podcast and episode forms, saving and the feed no longer have them. (`podcast:locked` stays as built in 0.8.0 because the spec and several directories use it; it is optional and blank by default.) Decisions 37, 39, 45 and 51 mention text records as they were at the time.
60. (0.9.1.) **Funding message default.** The Funding message box shows the hint "Support the show!" (the message used in the reference feed); a blank message is saved as "Support the show!". Over 128 characters is still refused.
61. (0.9.1, TODO 14.) **OP3 download counting, per podcast.** One tick box on the podcast page, "Count downloads with OP3", off by default (`op3` in the podcast details). When ticked, the feed's main `<enclosure>` address is written as `https://op3.dev/e,pg=<podcast guid>/<address without https://>` (an `http://` address keeps its `http://`; an address that already has the OP3 prefix is not prefixed again; only http and https addresses are changed). The address stored with each episode is never changed, so unticking restores plain addresses at the next feed write. Not prefixed: alternate files, transcripts, chapters, pictures, trailers, live streams. No own download log in WordPress (OP3 keeps the log). The page shows links to the statistics (`https://op3.dev/show/<guid>`, available after a few days) and to OP3's setup checker (`https://op3.dev/setup`), no pasted stats address. The owner did not answer the plan's open questions, so these are the defaults. The prefix format comes from OP3's published documentation as I read it; the `pg` parameter and statistics address should be checked with OP3's setup checker on a live feed.
